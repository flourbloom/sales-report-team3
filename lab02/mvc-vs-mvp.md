# Lab-02: MVC vs MVP

| Criterion                                   | MVC (ReportView + ReportController)                                                                                                                   | MVP (FxReportScreen + ReportPresenter)                                                                                      |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Lines of code (view / controller-presenter) | ReportView 102 / ReportController 48                                                                                                                  | FxReportScreen 98 / ReportPresenter 78 (+ ReportScreen 15, RowItem 5)                                                        |
| Tests that run without JavaFX               | 4 (ReportControllerTest): input handling only, no display text                                                                                        | 6 (ReportPresenterTest): status text, row formatting, money, error messages                                          |
| Where money and status text are formatted   | Inside `ReportView` (`String.format` in `modelChanged`, `revenue().toString()` in the column lambda): JavaFX class, so untestable without the toolkit | `ReportPresenter.money` and `modelChanged`: toolkit-free, covered by tests                                                  |
| Files changed to add a "Discount" column    | 1: `ReportView`                                                                                                                                       | 3 + 1 test: `RowItem`, `ReportPresenter.toRow`, `FxReportScreen`, plus `ReportPresenterTest` (record constructor changes)     |
| Does the view hold a model reference?       | Yes: `ReportView` keeps a `SalesModel`, listens to it and reads `branch()`, `visibleTransactions()`, `summary()`                                      | No: `FxReportScreen` has only setters and `attach(ReportPresenter)`                                                         |
| Effort for a second screen (web, Swing)     | High: every new view repeats the formatting and the model-reading logic                                                                               | Low: implement the 4 methods of `ReportScreen`; formatting and decisions are reused                                         |
