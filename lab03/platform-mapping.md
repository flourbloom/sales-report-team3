# Platform mapping: `ReportViewModel` on Android Jetpack and WPF

The JavaFX `ReportViewModel` holds state in observable properties, exposes actions as `Command` objects, and runs loading through `BackgroundJobs`. The table shows what each member would become on the two platforms head office is considering.

| ReportViewModel member                                                         | Android Jetpack                                                                                           | WPF (.NET)                                                                                                            |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `month` (`ObjectProperty<YearMonth>`, two-way)                                 | Private `MutableStateFlow<YearMonth?>`, exposed as `StateFlow`; the view calls `onMonthChanged(m)`        | Property with a backing field that raises `INotifyPropertyChanged`; `Mode=TwoWay` binding                             |
| `monthChoices` (`ObservableList<YearMonth>`)                                   | `StateFlow<List<YearMonth>>` (immutable list, replaced as a whole)                                        | `ObservableCollection<YearMonth>` bound to a `ComboBox`                                                               |
| Branch flags (`branchSelected(branch)`, one `BooleanProperty` per branch)      | `StateFlow<Set<String>>` of selected branches, toggled with `onBranchToggled(b)`                          | One `bool` property per branch, or a list of items with `IsSelected`, each raising `INotifyPropertyChanged`           |
| `productFilter` (`StringProperty`, two-way)                                    | `MutableStateFlow<String>`, updated with `onFilterChanged(text)`                                          | `string` property with `INotifyPropertyChanged`; `UpdateSourceTrigger=PropertyChanged`                                |
| `summaries` (`ObservableList<BranchSummary>`)                                  | `StateFlow<List<BranchSummary>>`                                                                          | `ObservableCollection<BranchSummary>`                                                                                 |
| `products` / `visibleProducts` (`FilteredList`)                                | `combine(products, productFilter) { ... }.stateIn(viewModelScope, ...)`                                   | `ICollectionView` over an `ObservableCollection`, with a `Filter` predicate                                           |
| `totalRevenue` / `totalRevenueText` (computed bindings)                        | `summaries.map { it.sumOf(...) }` then `.map { format(it) }` as derived `StateFlow`s                      | Read-only properties that raise `PropertyChanged` when `Summaries` changes (or `MultiBinding` with a converter)       |
| `loading` (`ReadOnlyBooleanProperty`)                                          | `StateFlow<Boolean>`                                                                                      | `bool IsLoading` property                                                                                             |
| `progress` (`ReadOnlyDoubleProperty`)                                          | `StateFlow<Float>`                                                                                        | `double Progress` property, updated through `IProgress<double>`                                                       |
| `status`, `loadError` (read-only strings)                                      | `StateFlow<String>` each (or one UI-state class)                                                          | `string` properties with `INotifyPropertyChanged`                                                                     |
| Validation: `monthError`, `branchError`, `validationMessage` (`StringBinding`) | Derived `StateFlow<String>` using `combine(month, branches) { ... }`                                      | `INotifyDataErrorInfo` (or computed string properties)                                                                |
| `canGenerate` (`BooleanBinding`)                                               | `combine(isValid, loading) { v, l -> v && !l }` as `StateFlow<Boolean>`; the button uses it for `enabled` | The `CanExecute` of the command; `CanExecuteChanged` is raised when inputs change                                     |
| `generateCommand` (`Command.execute()`, `executableProperty()`)                | `fun generate()` launched in `viewModelScope.launch { ... }`; enabled state comes from `canGenerate`      | `ICommand` (`AsyncRelayCommand`) with `async`/`await`                                                                 |
| `cancelCommand`                                                                | `Job.cancel()` on the stored job                                                                          | `CancellationTokenSource.Cancel()`                                                                                    |
| `BackgroundJobs` (`submit`, `JobListener`, `ProgressSink`)                     | `viewModelScope` with `Dispatchers.IO` for work; progress and results posted to `StateFlow`s              | `Task.Run` or `async`/`await` with `CancellationToken` and `IProgress<T>`; the `Dispatcher` marshals to the UI thread |
| `SummarySource` (data port)                                                    | Repository interface injected into the ViewModel                                                          | Service interface injected into the ViewModel                                                                         |
| `Clock` (injected for tests)                                                   | Injected `java.time.Clock` or a `TimeProvider` abstraction                                                | `TimeProvider` (.NET 8+)                                                                                              |

## What would not carry over

JavaFX lets the view write straight into `month`, `productFilter` and the branch flags through two-way binding, but a Jetpack `StateFlow` shown to the UI is read-only, so every input needs an event function such as `onMonthChanged(...)` and a private `MutableStateFlow` behind it (WPF keeps `TwoWay` binding, so this problem is specific to Jetpack). An Android `ViewModel` lives longer than the Activity and survives screen rotation, so it must never hold a reference to a view or a context, and the views have to re-collect its flows after every rotation, while the JavaFX ViewModel simply lives as long as the application creates it. The `Command` abstraction with `executableProperty()` has no Jetpack equivalent, so "can run now" becomes an ordinary `StateFlow<Boolean>` that the button reads, and in WPF it becomes `ICommand.CanExecute` with its own change event. The `Bindings` API (`createStringBinding`, `size`, `not`) and `FilteredList` do not exist in Compose or WPF, so derived values turn into `combine`/`map` operators on flows or computed properties that must raise change notifications by hand. Finally, our dashboard shares one ViewModel between two windows simply by passing the same object, whereas Android would need an activity-scoped or navigation-graph-scoped `ViewModel` (or a singleton) and WPF would need the same instance placed in both windows' `DataContext`.
